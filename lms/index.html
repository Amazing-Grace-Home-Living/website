FROM CHAT TO ACTION

Create an agent. Reach it from your phone.

Available here: model discovery, a text-response test, and chat for learning, design planning, and code advice. Separate setup: tool-enabled agents and remote computer access.

1. Create a custom agent in LM Studio
  1. On your computer, load a chat model suited to your hardware. For agents that act, choose one with reliable tool-use support.
  2. Give it a clear role and save the instructions as a Preset. Include its goal, the files or websites it may use, and how it should report results.
  3. Start with a small task and check its answer. A preset changes behavior; it does not grant access to your computer.

Example instructions: “You are my website assistant. Help me plan accessible pages and explain code changes. Work only in the project I select. Show me the proposed changes, test them, and ask before publishing, deleting files, or sending messages. Say clearly when you cannot perform an action.”

LM Studio preset guide ↗

2. Give the agent browser or project tools
  1. In LM Studio's Program panel, use Install → Edit mcp.json to add a trusted tool server following its instructions. MCP is the connection between a model and a tool.
  2. For browser tasks, Microsoft's Playwright MCP can provide browser navigation and interaction. Use a separate browser profile for agent work. Browser automation does not provide control of every desktop application.
  3. For programming, add a file or development tool with access limited to the intended project folder. A text model alone can suggest code but cannot save or run it.
  4. Test an observable task such as opening a public page and reporting its title. Inspect the actual browser and tool output. Configure confirmations in the tool or host for sensitive actions; instructions in a prompt alone do not enforce permissions.

Connect MCP tools ↗ · Microsoft Playwright MCP ↗

This web chat does not load your desktop presets or invoke MCP tools. A custom mobile agent interface would need LM Studio's tool-enabled API, authentication, a tool allowlist, action results, and cancellation. Tool-enabled API guide ↗

3. Use your computer and agent from a phone

Use the desktop app remotely: configure a remote-desktop service on your computer, then connect using its phone client. You can operate LM Studio and watch the agent's browser on the computer's screen.

  1. For example, set up your own computer at Chrome Remote Desktop, following its account and PIN setup.
  2. Connect from the supported mobile client with the same account. Keep the computer awake and online.
  3. Open LM Studio on the remote desktop, select your preset and tools, and try a small task. Review the results before approving consequential actions.

Official mobile remote-desktop instructions ↗

Advanced: use this chat through a private tunnel. First configure a private VPN and authenticated SSH access between your phone and computer. On Android, an SSH client such as Termux can forward the phone's port 1234 to LM Studio on the computer:

ssh -N -L 1234:127.0.0.1:1234 YOUR_USER@YOUR_PRIVATE_HOST

Replace the placeholders with your own SSH login and private computer address. On iPhone, use an SSH client that supports local port forwarding with the same source port and destination. Keep the tunnel active, then use http://127.0.0.1:1234/v1 above and the LM Studio API token if required. Browser local-network/CORS restrictions may prevent this hosted page from connecting; use the remote-desktop route if that happens. Phone background suspension can also interrupt tunnels.

A tunnel carries model requests; it does not add computer-control tools. Keep model ports private rather than forwarding them through your public router. Private-network setup ↗ · LM Studio API authentication ↗

A successful connection test proves only that the model replied. Agent tool access, remote access, and successful task completion must each be checked separately.

YOUR LEARNING PASSPORT

Keep your checkpoints with you.

Download a JSON backup of saved learning progress and restore it in another browser. This includes the learning campaign, RPG quests and choices, Code Matrix board, VIM/Bash checkpoint and review history, PowerShell Academy profile, legacy Matrix Academy passport, Signal Bonus balance and earned rewards, and Seven Stars locations.

It includes your chosen player name if saved. It excludes unrelated browser storage, credentials, unsaved combat frames, gameplay currency, and tower-upgrade loadouts. Signal Bonus balances merge by keeping the higher saved balance, so restoring the same file cannot duplicate credits. No file is uploaded to a server.

Review the merge before applying

    Merge keeps earned milestones, the furthest Code Matrix level, your existing story choices, and the higher Signal Bonus balance. Current VIM/Bash wave checkpoints take precedence. Close other game tabs before restoring, or reload them afterward; live combat frames are not in this backup.

    Your pace. Your progress.

    Lessons and puzzles remain replayable. Losing a mission keeps your earned progress. Completion XP and badges are awarded once; they do not buy quiz passes or unlocks.

    Progress lives in this browser on this site. It does not sync to an account. Browser data can be edited, so these results are for personal practice, not graded certification.
